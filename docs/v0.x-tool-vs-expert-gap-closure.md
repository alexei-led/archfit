# Tool vs expert: the v0.x gap-closure result

This is the closing deliverable of the gap-closure program (plan
`docs/plans/20260619-archfit-gap-closure.md`). It records, per language, how many
of the baseline blind zones the deterministic CLI now closes, what is now
deterministic, what only the off-gate LLM layer (`archfit review`) can narrate,
and what remains out of scope by design.

Method: we ran both `archfit` and an independent, blind `architecture:architect`
skill review on three real repos — archfit (Go), ccgram (Python, `src/` layout),
codegraph (TypeScript, no `node_modules`) — first to catalogue where archfit was
blind (baseline), then again after the fixes (Phase 2). The raw runs are in
[`docs/plans/notes/gap-closure-phase1.md`](plans/notes/gap-closure-phase1.md) and
[`docs/plans/notes/gap-closure-phase2-comparison.md`](plans/notes/gap-closure-phase2-comparison.md);
the final acceptance gate is in
[`docs/plans/notes/gap-closure-task21-acceptance.md`](plans/notes/gap-closure-task21-acceptance.md).

## Blind-zone count, before → after, per language

A "blind zone" here is one of the six baseline root-cause categories (coverage,
node-ID, distance/calibration, semantic/dynamic, synthesis, config-as-truth) that
produced a wrong, missing, or misleading signal on that repo at baseline.

| Language               | Baseline blind zones                                                                                                                                                        | After Phase 2 | Residual (and why)                                                                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-----------: | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Go (archfit)           | numeric BC score computed then discarded; every metric band `info`; no banded scorecard                                                                                     |   2 → **0**   | cohesion LOC-skew proxy reads internally-cohesive god-files as low — narrated by `review`, footnoted low-confidence                                  |
| Python (ccgram)        | change_locality false-0; 421 near-identical BC advisories; present gitnexus index ignored; 40+ lazy-hidden cycles; no synthesis                                             |   5 → **1**   | full cycle resolution through lazy/dynamic imports stays semantic — archfit **surfaces** the 788-site risk, does not resolve it                      |
| TypeScript (codegraph) | scip silently absent (no `node_modules`); martin flags node builtins (`fs`/`crypto`/`commander`); type-only vs runtime conflated; cross-internal cycle hidden; no synthesis |   5 → **2**   | config-as-truth: a flat single-`core`-layer config collapses distance → falsely-strong coupling (now _warned_, not corrected); full cycle resolution |

Net: of the six baseline categories, **four are closed deterministically**
(coverage transparency, node-ID consistency, distance/calibration, synthesis),
**one is surfaced report-only** (semantic/dynamic), and **one is partial**
(config-as-truth — warned, not auto-corrected).

The two hard _false_ signals from the baseline are gone: ccgram
`change_locality` reports **340** real cross-module edges instead of a false 0,
and codegraph martin lists **only first-party `src/` modules** instead of node
builtins. The 421-advisory flood collapses **7× to 58 scored rollups**.

## What is now deterministic

Every item below is computed without the LLM and is byte-identical across a
double-run (verified on all three repos; `config_hash` stable and identical
full == delta).

- **Correct change-locality across node-ID schemes.** Go `file:`, Python
  `module:` (including `src/` layout), and TS `file:` graphs all match changed
  files through the graph's own path mapping — no more language-specific false-0.
- **First-party-only graph metrics.** External / unresolved nodes (node builtins,
  uninstalled npm names) are excluded from instability / abstractness /
  martin_distance / blast_radius on both the dependency and the source side.
- **Numeric Balanced-Coupling score, surfaced and grouped.** Each BC edge carries
  `score_value` + `score_band`; near-identical edges are folded into deterministic
  rollups (`group_count` + representative member IDs), phrased in Vlad Khononov's
  vocabulary, and cohesion (high strength + low distance) is never flagged.
- **Distance for dotted/flat module names.** Dotted siblings (`a.b.c`) classify
  structurally instead of all collapsing to `DiffOwner`.
- **Volatility honesty.** `undeclared` (config gap → "declare subdomain/volatility"
  advice) is distinct from `unknown` (unresolved module → genuinely
  indeterminate). The BC score documents `Effort ∝ Strength × Distance ×
Volatility` as _archfit's deterministic implementation of Vlad's qualitative
  heuristic, not a literal published equation_.
- **Coverage states its reason.** A metric that is `n/a` because a tool is
  missing/opt-in now reports the reason and the enable step (TS `risk_hub` →
  "install node_modules"; `complexity` → install lizard; gitnexus →
  present-but-disabled vs no-index vs no-CLI).
- **gitnexus auto-detect.** A present `.gitnexus/` / `.codegraph` index is used
  automatically (three-state `on` / `off` / auto); archfit only reads it.
- **complexity for Python and TypeScript.** lizard now runs for all three
  languages (explicit `-l` flags; non-zero "found hot functions" exit handled).
- **Dynamic / lazy import signal (report-only).** Python in-function /
  `importlib` / `__import__` and TS `require()` / dynamic `import()` are counted
  per module with sample sites — the deterministic pointer at the cycles the
  static graph cannot see. Does not alter the graph or any metric.
- **Config-quality lint.** Modules omitting `owner` / `subdomain` / `volatility`
  are warned on stderr (explains advisory floods and degraded distance) without
  touching the stdout contract.
- **Banded 7-dimension scorecard.** `archfit score` / `--format scorecard`
  synthesizes metrics + gates into the architect rubric's dimensions
  (value / band / confidence / evidence), with band-matches-value and
  evidence-per-score enforced, and a stored golden.

## What remains LLM-only (`archfit review`)

`archfit review` feeds the full deterministic evidence bundle to the LLM with
schema-constrained output. It may only narrate dimensions, classify
volatility/subdomain, dedupe/prioritize **existing** findings, and propose the
banded scorecard; a post-verify pass drops any module/metric it cites that is not
in the evidence, and it never affects `check` (LLM-off-gate invariant,
`internal/arch_test.go`). It is exactly the diagnosis layer behind the three
systematic tool-vs-expert divergences:

1. **Cohesion context.** archfit's cohesion proxy penalises LOC-skew god-modules;
   it cannot see that a large file is internally well-factored, or that small
   sub-packages are strongly cohesive. `review` narrates that.
2. **Enforcement-aware boundary judgment.** archfit scores the current violation
   count; the expert credits the _discipline_ that defends a boundary (AST fitness
   tests, lazy-import allow-lists). `review` reads enforcement posture from the
   evidence.
3. **Intent over config-as-truth.** Where a flat config collapses distance,
   `review` distinguishes an intentional library-facade fan-out from a
   distributed-monolith edge — reasoning archfit's classifier cannot do from globs
   alone.

## What remains out of scope by design

- **Full semantic cycle resolution through lazy/dynamic imports.** Needs runtime
  tracing or complete SCIP. archfit surfaces the risk (the dynamic-import signal)
  but does not resolve the hidden cycles.
- **Declared-vs-observed config drift.** archfit _warns_ that a config is
  under-specified (config-quality lint); it does not flag a flat/under-specified
  config as _wrong_ against observed structure.
- **The architect POV diagnosis layer.** Intent, ownership, contract, and
  placement judgments are deterministically surfaced as locations and metrics;
  they are _narrated_ only by `archfit review`, never gated.

## Determinism and acceptance

All nine JSON/scorecard double-runs (full / delta / scorecard × 3 repos) are
byte-identical; each repo's `config_hash` is stable and identical across full and
delta. `make all` (fmt → lint → test → build) is green, including the core-ring
import invariant (`TestArchImports`), the golden test (`TestGolden`), and the
LLM-off-gate invariant. See the acceptance note for the 17/17 assertion run.

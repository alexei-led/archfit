# bc_score.v4 — strength & distance classification fixes (Wave 4)

Status: in progress (branch `fix/wave1-gate-integrity`, wave 4 of the
2026-07-02 eval remediation). Formula unchanged — still Khononov Ch10
verbatim: `balance = max(|S−D|, 10−V) + 1`. What changes in v4 is the
classification feeding the formula. Ordinal assignment changes are a
breaking metric change (CLAUDE.md), so the version bumps once, up front,
and **v4 scores are not comparable to v3 scores**.

Source findings: `reports/eval-2026-07-02-v1.1.2/00-FINDINGS.md` §1
(deviations 1–3) and `book-conformance.md`.

## The three classification changes v4 covers

1. **Go const/var reads score Model (S=3), not Functional (S=8).**
   Referencing another module's exported const/var is pure data sharing —
   the book's Model coupling (Ch7). The Go extractor mapped the resolved
   object kinds `const`/`var` to `functional`, a 5-point error on a
   10-point ordinal scale, unfixable by config. Funcs stay `functional`,
   interfaces stay `contract`, concrete types stay `model`.

2. **Pure-data DTOs reach Contract (S=1) in Go.** An exported struct with
   only data fields and an empty method set, referenced across a
   config-declared `public:` glob boundary, upgrades the public-glob floor
   from not-intrusive to `contract` — the book's canonical Contract example
   is exactly a concrete integration DTO. Anything with methods or
   unexported fields stays `model`; a DTO not crossing a declared public
   boundary stays `model` (the boundary declaration is what makes it a
   contract). TS/Py/Rust have no equivalent static signal and abstain;
   Wave 7's LLM labels are the designed path there.

3. **D=10 rung for declared external systems.** New frozen ordinal
   `DistanceExternal = 10` (book Ch10 Example 1, cross-vendor integration).
   Edges matching a config-declared `external_systems:` entry enter scoring
   at D=10 (default volatility low, per the book's generic-subdomain
   guidance). Undeclared external edges keep the disclosed exclusion
   (`classified_edges.external`) — scoring every library import at D=10
   would flood the metric with vendor noise; the book's example is a
   _declared integration seam_.

## Consumer impact

- `score_version` now appears at the top level of `--json` output (always
  present), in addition to per-finding `matched_by.score_version` on BC
  advisories. Consumers key on it; treat a version change as a new
  measurement, not a delta.
- Baselines storing a v3 `score` snapshot must be re-baselined before
  `coupling.gate.max_drop` comparisons are meaningful again (Wave 4 Task 5).
- Attribution: `make corpus-attrib` prints the coupling_balance
  score/band/scored/abstained/external row per attribution repo (archfit
  Go, ccgram Python, herdr Rust, storybook TS) for the before/after tables
  in `docs/plans/20260702-wave4-book-strength-distance.md`.

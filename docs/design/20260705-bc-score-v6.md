# bc_score.v6 — inferred volatility cascade is transitive

Date: 2026-07-05. Status: shipped.

## Decision

`ScoreVersion = "bc_score.v6"` because the opt-in inferred-volatility semantics changed. The book formula, ordinals, severity bands, and abstain rules did not change. The cascade now runs to a deterministic fixpoint instead of reading only base volatility for a single hop.

Config remains unchanged:

```yaml
coupling:
  volatility_cascade: true
```

When enabled, a module strongly coupled (`functional`, `symmetric`, or `intrusive`) to a high-effective-volatility module inherits high effective volatility for scoring. Because the pass is a fixpoint, a chain such as `A → B → core` can raise both `B` and `A` when both edges are strong deliberate integrations.

Clone-only duplicated-knowledge pairs are still excluded from the cascade. They are accidental coupling evidence, not proof of a runtime/domain dependency that should raise a whole module's volatility.

## Why this is score-versioned

Scores are not comparable between `bc_score.v5` and `bc_score.v6` when `coupling.volatility_cascade: true` is enabled. Edges that previously saw only base volatility can now see transitive high volatility through strong-coupling chains. This can lower the volatility rescue term for some edges and change `coupling_balance`.

Repos with `coupling.volatility_cascade` off keep the same effective-volatility behavior as v5, apart from the version literal in output.

## Runtime coupling remains report-only

This version does not score runtime/lifecycle distance. Runtime async evidence is now available at two report-only levels:

- `runtime_async`: per-module rollup;
- `runtime_async_edges`: source-module → runtime-target relationships with concrete sites.

Both fields are prerequisites for later review. Neither annotates graph edges, changes distance, enters `coupling_balance`, affects baselines, or changes gate verdicts.

## Non-Go strength refinement

SCIP symbol-kind metadata is now consumed where available before falling back to descriptor suffixes:

- interface/protocol/trait/abstract kinds → `contract`;
- concrete data/type kinds → `model`;
- function/method kinds → `functional`.

The built-in TypeScript/Python extractors remain conservative when SCIP is absent. No LLM-derived label enters scoring unless it is reviewed and pinned through the existing approved-label path.

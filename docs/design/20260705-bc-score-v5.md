# bc_score.v5 — clone-only duplicated knowledge enters the headline score

Date: 2026-07-05. Status: shipped.

## Decision

`ScoreVersion = "bc_score.v5"` because the default headline score semantics changed. The book formula, ordinals, and severity bands did not change. The denominator changed: clone-only duplicated-knowledge pairs now enter `coupling_balance` by default.

New config:

```yaml
coupling:
  duplicated_knowledge: score # score (default) | advisory
```

- `score`: include cross-module clone pairs with no import edge in `classified_edges` and `coupling_balance` as `StrengthSymmetric` coupling facts.
- `advisory`: preserve v4 behavior; clone-only pairs can emit `bc/duplicated_knowledge` advisories but stay out of `coupling_balance`.

The default is `score` for book fidelity. Khononov Ch7 treats duplicated functional knowledge as coupling even when no import edge exists; leaving it advisory-only kept a flagship-score blind spot.

## Output changes

`classified_edges` now exposes:

- `clone_only_scored`: clone-only pairs included in `coupling_balance` by policy.
- `clone_only_advisory`: clone-only pairs held out by `coupling.duplicated_knowledge: advisory`.

The `coupling_balance` evidence line includes:

```text
clone-only duplicated-knowledge pairs: S scored, A advisory-only
```

`bc/duplicated_knowledge` advisories remain advisory findings. The coupling gate promotes only `bc/imbalanced_coupling`; clone-only advisory promotion is deliberately unchanged.

## Migration

Scores are not comparable between `bc_score.v4` and `bc_score.v5`. Re-run `archfit baseline` after reviewing the attribution below. Do not treat a `max_drop` skip across this version boundary as a regression.

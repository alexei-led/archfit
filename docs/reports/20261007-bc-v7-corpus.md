# Seam census: bc_score.v6 against bc_score.v7

This report records what `bc_score.v6` flags on the corpus, and what
`bc_score.v7` flags on the same checkouts. The v7 result and the verdict are
at the end.

## Method

- Binary: archfit built from `664fd7d` (v2.5.0 plus the two v2.5.1 fixes).
- Tool: `scripts/eval/seam_census.py`, one `archfit analyze --format json` run
  per repository.
- Checkouts: disposable `git clone --local` copies at the HEAD of the owner's
  clones. The owner's clones are not touched.
- Configs: the config of each clone. prometheus, yazi and ruff are on schema
  v1, so their copies only change `version: 1` to `version: 2`. None of them has
  a retired `coupling.gate` key. The migrated configs are not committed.
- Rust runs use `RUSTUP_TOOLCHAIN=1.98.0`.

## Reading the numbers

- **archfit:** 72 seams. All sit at `cross_module_same_owner` (D=4). 43 are
  functional, 11 model, 9 contract and 9 symmetric. Nothing qualifies, because a
  seam needs a high distance and the repository has one owner and one deploy
  unit. This is the defect that v7 fixes.
- **pumba:** 7 seams, all functional at D=4. One is critical.
- **ccgram (Python):** only 3 scored edges and no seam. Python has no strength
  signal without a `public:`/`internal:` glob or SCIP.
- **prometheus:** 487 seams, 34 of them qualify under v6. The seams come from
  the CODEOWNERS owner split (`cross_module_different_owner`, 141 seams). The first
  qualifiers listed are between `model_*` modules. The v7 review checks them by hand.
- **yazi and ruff (Rust):** almost every edge abstains (98.6% and 100%). These
  runs have no SCIP index and no `cargo_modules`, so crate edges have unknown
  strength. v7 cannot change an abstained edge. Do not read these two rows as
  evidence for or against v7.

Binary: archfit built from `eee4f2a` (all of V1 PR0 to PR2). Same checkouts,

The seam count does not change on any repository: seams come from the module
pairs, not from the score. The score and the qualification change. The high
band is gone, because a module boundary is always D=9.

## Hand review of the qualifying seams

- **archfit (5).** `analysis-application`, `evidence-acquisition` and
  `policy-config-adapter` call the entry points of `assessment-repair`,
  `relationship-analysis` and `evidence-adapters`. These entry points are
  documented in CLAUDE.md, but the self-config does not declare them `public:`.
  The finding is correct for the config as written: the call is a concrete call
  into a non-public surface of a high-volatility core module. The fix is a
  `public:` declaration, which is an owner decision. The self-config stays
  `mode: warn`.
- **pumba (2 critical, 0 qualifying).** Both seams start in a cohesive source
  role (`expected_by_role`). The gate does not count them. This is the intended
  result.
- **prometheus (3).** `model_textparse` and `storage_remote` call `prompb_io`,
  and `util_annotations` calls `promql_parser`. All three are functional calls
  into a concrete module with high volatility, hypothesis `introduce_contract`.
  v6 qualified 34 seams, mostly between `model_*` modules that differ only in
  the CODEOWNERS owner set. Owner no longer changes severity, so these drop out.
  Not checked by hand: whether the high volatility of the three targets is a
  declared judgment or inherited from a default.
- **yazi (2 critical).** Both seams come from the 3 edges that have a strength.
  The other 207 edges abstain as before.

## Verdict

v7 flags the right things on the two repositories where the inputs are rich:

- v6 flagged 26 critical seams in archfit and 51 in prometheus from owner and
  key spelling alone. v7 flags 13 and 3, and each qualifier is a concrete call
  across a module boundary into a high-volatility module.
- The ordering is correct now: a call through a port or a `public:` surface is
  contract and never flags; the same call into a non-public package does.
- A cohesive role (composition root, generated, test) stops being a source of
  qualifying seams. pumba shows it.
- Python (ccgram), Rust (yazi, ruff) are unchanged because their edges abstain
  or have no strength signal. They are not evidence for or against v7.

Open caveats: the census is one sample per repository. `mode: fail` needs an
owner review of the qualifiers first, as for v6. TypeScript has no census.

## Limits

- TypeScript (storybook) is not in this census. v7 flags TypeScript runtime
  imports as functional when SCIP is absent, so the TypeScript result needs its
  own run before anyone sets `mode: fail` there.
- A repository at HEAD is one sample. The numbers show the shape, not a rate.

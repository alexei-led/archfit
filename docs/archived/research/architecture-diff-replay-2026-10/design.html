Archfit · Design notes
Open prototype · 40-PR replay

Short for people. Complete for agents.

One review flow. No new product modes, scores or mandatory AI commentary.

Human first screen

  1. Merge effect: advisory or evidence needed.
  2. Change: one factual headline and a focused before/after diagram.
  3. Next: one concrete check.
  4. Action: view evidence, view a policy diff, or show recovery steps.

Existing App tokens, compact boxes, Findings / Graph tabs, light/dark themes and progressive disclosure. No new sidebar or navigation system.

Agent handoff

Copy review task copies JSON with the case, source evidence, comparison scope, constraints, validation and existing result.

Nothing runs automatically. It grants no merge, waiver or policy-edit permission.

On GitHub, the payload stays in a folded code block. In the App, copying is a real button with success feedback and a manual-copy fallback.

Jev/Clef has one bounded job

Classify the transformation—not whether the code is “good,” and not whether a PR may merge.

1 · Tools + Git

Establish facts

Exact references, source changes, policy, scope and completeness.

2 · Engine

Route the event

Skip models for docs-only, policy-only or incomplete evidence.

3 · Optional Jev or Clef

Select a label

Callback extraction, responsibility move, contract expansion, relocation—or insufficient context.

4 · App

Use a template

One interpretation and a bounded review focus. Facts-only fallback always works.

Input · illustrative, not a vendor API

{
  "before": "handler writes private runtime state",
  "after": "handler invokes a supplied callback",
  "intent": "runtime owns restart state",
  "evidence": ["source diff", "resolved reference"],
  "context": "bounded old/new source",
  "allowed_labels": [
    "private_state_to_callback",
    "responsibility_move",
    "dependency_relocation",
    "insufficient_context"
  ]
}

Output · simulated

{
  "transformation": "private_state_to_callback",
  "review_focus": "preserve_restart_sequence",
  "authority": "advisory_only"
}

No actual model calls or calibrated probability are shown. Typed output is easier to validate, not guaranteed correct.

The classifier cannot invent a removed edge, hide a blocker, fill missing evidence, prove behavior, or change approved policy.

Automation, privacy and fallback

Required checks always run. Only optional interpretation is routed. Refusal, timeout, invalid output or abstention retains factual events. Repository prose is untrusted data, not model instructions.

Source-aware inference stays in customer CI or needs additional sharing consent. Record model/configuration, prompt and input identities. Customer-attested reports are not independent execution proof.

In the prototype, open Test options to compare the simulated label, facts-only and abstention. The existing result never changes.

Why the five cases behave differently
  • #341 / #350: show the observed structural change; optionally interpret the refactoring.
  • #342: policy-only change. Compare policy, not code quality. No model.
  • #363: docs-only change. No new architecture comment. Keep check and repository attention.
  • Missing base: unknown, not green. Show recovery steps. No model.
What is existing, proposed and still unproven

Existing: policy, graph evidence, findings, comparison identities, governance, agent tasks, PR comments and App pages.

Proposed: exact member-level change events, resolved-change summaries, contextual transformation labels and quieter presentation.

Unproven: extra prevented defects, reviewer time savings, classifier value and willingness to pay. The replay found existing useful signals and substantial overlap with other review tools.

Compare deterministic templates with templates plus classifiers on held-out cases. Keep a model only if it improves correct decisions without hiding important evidence.
